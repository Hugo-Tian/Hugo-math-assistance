# 约 3 分钟作品集演示

演示前：按 README 启动前后端，使用 Chrome/Edge 打开 http://127.0.0.1:5173 。演示初始账号不要反复提交同一题以免混淆状态；需要完整从零流程时注册新账号。以下只描述实际实现。

| 时间 | 操作 | 讲解重点 |
| --- | --- | --- |
| 0:00–0:25 | 用 demo_foundation 登录，显示首页推荐，展开“为什么推荐这项任务” | 同一公式包含薄弱、复习、目标三项贡献；账号有 20 条明确标注的模拟记录，当前推荐函数单调性 |
| 0:25–0:45 | 退出后用 demo_advanced 登录，目标保持闭区间最值 | 相同学习目标、不同答题历史，推荐变为导数计算；不宣称提高成绩 |
| 0:45–1:05 | 打开知识树，依次点击导数计算、函数极值、闭区间最值 | 不同 ID 对应不同详情；最值有极值和二次函数两个先修；未评估不显示 50% |
| 1:05–1:40 | 开始自适应练习，选择答案并提交；展示解析与掌握度，再点下一题 | 服务器判题，同步保存尝试、更新掌握度和错题；下一题在提交后重新选择。演示账号前 5 道基础题已曝光，系统优先派发未见题 |
| 1:40–2:05 | 打开错题本，选择一道待复习题，完成针对性复习 | 错误次数和最近时间真实记录；看过答案的重复练习保留但不再次增加掌握度 |
| 2:05–2:25 | 打开学习报告，选刚练过的知识点，刷新页面 | 总量、正确率、样本数与趋势来自同一份历史；刷新保留数据；模拟记录明确计数 |
| 2:25–2:45 | 搜索“切线”，筛选中等；再自定义切线中等 10 题 | 搜索只有 3 题，自定义如实提示不足，只派发 3 题；没有伪造题量 |
| 2:45–3:00 | 展示管理员工作台或测试结果文档 | 先修环路/非法 JSON 拒绝，题目编辑保留历史版本；展示真实测试与 MySQL 并发验证 |

## 更清楚的冷启动闭环（可替换上述 1:05–2:25）

注册一个新账号，首页推荐集合运算。开始自适应练习，第一道集合交集题的正确答案为 3；刻意选择 2 并提交，得到 1/3≈33% 的掌握度、1 条有效样本和一条错题。打开知识树、错题本、报告，三处数据一致。刷新后仍为同一结果。再复习此题答对，错题变为已复习，掌握度仍为 33%，因为答案已曝光；全部尝试正确率变为 50%。这一差异能说明系统没有把“记住答案”包装成掌握提升。

## 固定顺序与自适应的行为差异

初始演示账号的下一点可能与固定顺序一致，这是符合事实的，不要为了演示刻意描述为不同。后端测试 `test_recommendation_returns_to_failed_prerequisite` 提供可复现的分歧：

1. 新账号对集合的 5 道基础题全部答对，集合通过，下一步是函数定义域。
2. 对集合的 3 道中等新题连续答错，掌握度从 6/7 变为 6/10=60%；集合历史成就仍保留。
3. 固定章节顺序仍推荐定义域；自适应先检查当前先修缺口，返回集合运算进行复习。
4. 测试同时断言两项输出，没有做成绩、留存率或学习效果实验。

## 中文简历项目描述（选择 3～4 条）

- 基于 Vue 3、Pinia、FastAPI 与 SQLAlchemy 实现高中数学自适应学习管理系统，贯通答题持久化、错题复习、知识点掌握度、动态推荐和学习报告，提供学生与管理员角色及 MySQL 数据库迁移。
- 设计含 14 个独立知识点和多先修关系的 DAG，实现环路检测、最近 20 条有效记录的平滑正确率、历史通关保留及可解释推荐，返回推荐因子、加权贡献和算法版本。
- 实现服务端判题、答案曝光约束、幂等提交与事务更新，结合用户行锁、唯一约束及 MySQL READ COMMITTED 解决并发重试一致性问题；验证后端进程重启后的数据保留。
- 构建 140 道明确标注的参数化演示题并进行独立数值核验，编写并通过 17 项后端/题库测试及 4 条浏览器端到端测试，验证权限隔离、先修修复、题目筛选、重复计分防护与跨页面数据一致性。

可用项目名：**知序——高中数学自适应学习管理系统（个人作品集项目）**。

不要添加未经验证的“服务数千学生”“推荐准确率提升”“学习效率提升”“高并发性能提升”，也不要写成训练了机器学习推荐模型。参数化题库不等于 140 种独立命题；项目尚未投入真实学校教学。
