# 高中数学智能学习助手：实现与边界

## 2026-10-16 边界补充

- 最终回答通过 `AssistantOutput` 严格校验：answer、citations、plan 必须存在，不接受额外字段；计划对象仍经独立业务校验，保留一次修复和明确规则降级。
- 生成期间重新读取文档权限；历史读取/幂等重试会过滤已失效引用，隐藏依赖失效来源的历史回答，且不再把该回答送入后续模型上下文。已交付到客户端的内容无法远程撤回。
- 单工具等待时间受剩余请求总预算限制。后台只读线程在等待取消后仍可能短暂运行，不宣称强制中断线程。超时下未确认的 HTTP 尝试总数为未知。
- 页面执行记录展示工具成功/失败、耗时、模型轮次、HTTP 尝试和实际 usage；缺失/无效 usage 为未知。执行记录不等于回答质量评分。
- 无作答记录的计划明确标注尚未评估；模型草稿依赖实际 profile、wrong questions、prerequisites、recommendation 工具。保存及开始仍走原业务接口。
- 当前验证范围及简历表述见 [本轮报告](VALIDATION_20261016.md)，下文历史验证结论不得替代本轮真实 API/MySQL 验收。

## 当前工程检查与复用

升级前已有 Vue 3 / FastAPI / SQLAlchemy、MySQL 与 SQLite、认证及角色权限、14 点先修 DAG、140 道参数化题目、掌握度、推荐、错题、报告、幂等与事务。此前知识树已改为思维导图，闯关保持卡片。以上继续复用；LLM 不参与判题、掌握度更新或直接数据库写入。

新增代码均位于原工程：`backend/ai/` 为模型、RAG、Agent、计划和 API；`src/pages/Assistant.vue` 为学习助手；`KnowledgeAdmin.vue` 为知识库管理。没有另外建立脱离业务的聊天产品。

## 模型服务层

`provider.py` 定义 Provider 协议并实现 DeepSeek Chat Completions。按照[官方工具调用协议](https://api-docs.deepseek.com/guides/tool_calls/)执行：模型返回 `tool_calls` → 服务端校验/执行 → 以 `role=tool`、相同 `tool_call_id` 回传 → 模型再次生成。默认模型使用官方非思考工具调用示例的 `deepseek-flash`，通过环境变量可改；请求显式关闭 thinking，要求 JSON 最终回答。实际账户可用模型仍需要真实 API 冒烟核验。

模式严格区分：

- `LLM_MODE=real`：必须有 LLM_API_KEY（或 DEEPSEEK_API_KEY）；无Key、超时、限流等均作为失败/未配置反馈，不改用Mock。
- `LLM_MODE=mock` 且 `ALLOW_TEST_MOCK=true`：只用于显式测试，固定模拟工具调用，UI标“测试Mock”。这个实现不是LLM、不会被描述为真实Agent能力。
- 每个请求有UUID追踪；服务端不打印Key、Authorization或上游原始错误体。上游错误归类为 not_configured、auth、rate_limit、upstream、invalid_request、timeout、network、invalid_response、incomplete。
- 默认单次HTTP超时25秒，最多1次重试（配置硬上限2）；只重试超时、网络、限流、5xx。Agent总时限100秒、最多4轮、8次工具执行；单工具12秒。输出上限1600Token、请求预算64000Token。
- 提供方usage缺失时显示未知。预算预检使用UTF-8字节数加输出上限作为保守上界，**不能当作实际Token统计**。上下文最多14000字符，历史仅取最近6个成功轮次且限制字符预算；工具消息保持原协议成组处理，过长则明确拒绝而非无限累积。
- 本版采用整段完成式请求，不实现SSE。只有拿到完整、校验后的回答才标completed；异常为failed。pending在下一次请求时超过时限会标记服务中断。浏览器断连不意味着回答内容成功送达；再次打开会话可以读取服务端最终状态。

## 知识库与索引

42 条实质讲义由 `materials.py` 自编，覆盖全部14点；每点3个条目，标注“自编演示资料”，没有导入官方教材。种子资料与固定评测集是分开的文件和调用路径。真实 Embedding 采用[FastEmbed支持的中文 BGE-small-zh-v1.5](https://qdrant.github.io/fastembed/examples/Supported_Models/)，通过ONNX在CPU运行，512维，无随机向量替代。

选 FAISS 而非 Chroma：本项目规模小，业务权限和元数据已有SQL数据库，不需要再引入一套元数据服务；FAISS `IndexFlatIP` 加单位化向量即可实现精确余弦排序，便于复现和检查。不是近似检索性能演示。

导入支持 UTF-8 MD/TXT 和文本型PDF，5MB/100页/25万字符上限。扫描/无文本页面、加密PDF、损坏格式、空文本均明确失败；内容checksum拒绝重复文件。失败文档保留status/error，可在管理员页面删除后修正重传。源码文件名不作为磁盘写入路径，内容存SQL，不执行文档指令。

切分优先遵循标题与空段落，保持 `$$...$$` 和代码围栏完整；片段目标1100字符，单个不可分原子块超过3300字符拒绝，要求人工分段，不机械截断推导。保存document_id、chunk_id、标题、章节、页码、知识点、文档版本和来源。未闭合公式块拒绝。版本默认1；更新资料采用新文档/重新导入，不提供静默覆盖历史内容。

SQL是真实来源，FAISS是可重建缓存：

1. 导入后SQL提交parsed，关键词立即可用；点击重建后才进入向量索引。
2. 重建用文件锁、不可变版本文件和原子manifest切换；manifest含模型名、ONNX权重SHA-256、维度、片段ID与内容哈希。
3. 每次检索先取得SQL授权候选，再从向量排序结果中只保留仍活跃、仍存在、内容哈希一致的候选。停用或删除立即不再召回，不依赖异步清理成功。
4. 建索引失败时SQL文本仍保留，旧manifest仍可读；可以显式配置RAG_MODE=keyword，或修复缓存后重建，**不会静默从向量切成关键词**。
5. 模型名、权重指纹或维度不一致时要求重建。默认只读本地模型，只有初始化脚本 `--download-model` 明确允许下载。
6. 历史FAISS版本文件保留在本地忽略目录；重建当前索引不代表物理擦除所有旧向量文件。用户文档删除后不能再检索，管理员如需磁盘清理应在停机备份后处理旧版本。

## 检索与引用

链路：认证/测验保护 → SQL候选权限过滤 → 关键词或向量排序 → Top-K/阈值/上下文长度筛选 → 组织不可信资料包 → 模型生成 → 引用ID校验 → 再检查当前权限与文档状态 → 发布回答及来源卡片。

关键词基线对中文使用二元字组、对英文数字用词项；分数为查询词项被文本覆盖的比例，不是BM25。向量为归一化内积，不是回答正确概率。未实现混合或reranker，不声称具备这些能力。

默认Top-K=5、引用上下文5000字符、关键词阈值0.08、向量阈值0.65。向量阈值仅在dev上比较0.55/0.60/0.65后选择，最终集不参与调整。检索无证据的RAG请求返回明确资料不足提示，不调用模型自由回答。

引用只能指向本次初始检索或search_knowledge返回的ID；未召回引用导致回答失败，不给模型伪造链接。前端来源卡调用认证 `/assistant/sources/{chunk_id}` 查看原文，已停用/删除/失去权限后返回404。任意模型URL被移除，Markdown中的链接/图片不会发起导航或加载，原始HTML转义，再用DOMPurify清洗。KaTeX trust=false。

## 测验和数据权限

公共讲义与题目解析以scope区分。题目解析仅在当前用户有该题Attempt后可检索；其他学生做过不产生授权。错题讲解的题干、答案、解析、选项与用户作答从保存的题目版本和Attempt读取，不接受前端答案参数。

采取保守测验保护：**当前用户只要有任何未提交题目的练习会话，就暂停所有详细AI问答与RAG，只返回通用提示**。这也拦截把题目复制到独立聊天、伪装成老师等绕过尝试。UI可由用户明确“结束未完成练习，继续学习辅导”；此操作结束本人会话，不改已交记录/掌握度。不假称能在任意自由问题上可靠判断模型是否间接泄题。

即使没有活跃会话，只要绑定的question_id未提交也只给提示。计划工具全部只读；模型不能提交答案、改成绩、执行代码、选择user_id或访问文件系统。数据库/文档内容不会变成工具定义。对话和来源API都要求认证，会话所有权由数据库验证。

## 工具Schema

`tools.py` 中注册的六个工具是唯一白名单。Pydantic使用 `extra=forbid, strict=True`，禁止额外user_id，整数不接受字符串，知识点必须存在。工具Schema实际导出为 `docs/AI_TOOL_SCHEMAS.json`。

| 工具 | 参数 | 返回 |
| --- | --- | --- |
| get_learning_profile | {} | 本人目标、全部/有效答题量、模拟标志 |
| get_mastery | knowledge_id:string | 本人该点掌握度、样本数和状态 |
| get_wrong_questions | limit:int，1～10 | 本人最近错题、保存的答案/解析、作答与复习状态 |
| get_prerequisites | knowledge_id:string | 必要先修及当前缺口 |
| recommend_practice | {} | 原规则推荐及确定性计划结构参考 |
| search_knowledge | query:string，2～300字符；knowledge_id可空 | 本次授权证据与索引版本 |

不是按关键词if/else选择工具。生产工具执行只接受模型返回的tool_calls；Mock固定返回六个调用只是协议夹具。工具失败返回明确error，追踪表记录工具名、经过校验/脱敏的参数、状态、耗时；查询文本只记录长度，不把敏感内容写入调试日志。后台页面才能查看追踪。

## 计划草稿与写入

三天结构由Pydantic校验：day严格为1/2/3；每天1～3个任务；每任务1～10题、估算5～90分钟；每日估算≤180分钟；知识点与题目存在、题目活跃且属于指定知识点、题量足够，不接受额外user_id。

当前缺少先修时，后续任务必须排在相关先修任务之后，并标 conditional_on_pass=true；不能假设计划完成就掌握。真正点击开始时重新检查当前先修，未满足返回409。

模型计划必须有实际profile/prerequisite/recommendation工具依据；非法计划只允许一次修正，再失败则返回规则推荐草稿并明确origin=deterministic_fallback。降级不会伪装成模型成功优化，也不会写入学习状态。

保存接口锁用户行，request_key和user/turn唯一约束防重复；开始练习按plan/day/task唯一约束幂等，调用原start_session并重新检查题库。用户点击“开始练习”会先保存该草稿，再走正常业务接口；练习提交仍由原后端判题。
